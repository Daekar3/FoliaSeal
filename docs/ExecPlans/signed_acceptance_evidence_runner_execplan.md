## Purpose / Big Picture

FoliaSeal can now generate signed acceptance inputs and run each signed-output matrix, but contributors still have to remember a multi-command sequence and manually inspect three summaries. After this change, one tracked command will regenerate the current-code assets, run the representative acceptance, preview-parity, and fit-rejection matrices, validate their summary counters, and write a concise local evidence note under `artifacts/`. The visible behavior is that `foliaseal phase3-signing-acceptance-evidence` succeeds only when the signed-output acceptance proof is green and raises on any mismatch.

This is a tooling and evidence-enablement slice. It must not change signing behavior, visible-signature layout behavior, manifest payload semantics, or the low-level matrix harness.

## Surprises & Discoveries

- Observation: `run_phase3_signed_acceptance_matrix()` already evaluates manifest acceptance expectations, but it returns a summary instead of failing the process.
  Evidence: `src/foliaseal/presentation/qt/phase3_harness.py::run_phase3_signed_acceptance_matrix()` writes `summary.json` and sets `acceptance_expectations_passed`, `expected_outcome_mismatch_count`, and related counters.

- Observation: the CLI contract is explicitly user-facing.
  Evidence: `docs/ARCHITECTURE.md` says `src/foliaseal/__main__.py` commands are documented in README and covered by CLI tests, so new commands need parser and dispatch coverage.

- Observation: a failing evidence run still needs a local evidence note when a matrix crashes before returning a summary.
  Evidence: compliance review identified that the first-pass runner propagated pre-summary matrix exceptions before writing markdown. The runner now records an error row for that matrix, writes a failure markdown note, and then raises `RuntimeError`.

## Context and Orientation

The signed acceptance assets are generated by `src/foliaseal/application/qa_signed_acceptance_generation.py`. That module writes the ignored local fixture PDF, test PKCS#12 identity, stamp image, and manifests. The signed matrix runner lives in `src/foliaseal/presentation/qt/phase3_harness.py` and is already exposed by `foliaseal phase3-signing-acceptance-matrix`.

A matrix summary is the JSON result produced by one signed matrix run. It records whether manifest expectations passed, how many scenarios succeeded, how many intentional rejections matched, and whether cryptographic validation, preview/output comparison, or annotation rectangle checks failed. The new runner should treat a summary as passing only when `acceptance_expectations_passed` is true and all critical failure counters are zero.

## Plan of Work

Add a Qt presentation evidence module, `src/foliaseal/presentation/qt/phase3_signed_acceptance_evidence.py`. It should expose `run_signed_acceptance_evidence(...)` and a small validation helper. The runner should regenerate assets, run all three manifests into stable ignored output directories under `artifacts/`, validate each returned summary, write a concise markdown evidence note, and raise `RuntimeError` with actionable messages if any manifest fails. This module lives beside the Qt-backed matrix harness because it directly orchestrates that harness.

Add a CLI subcommand in `src/foliaseal/__main__.py`, named `phase3-signing-acceptance-evidence`. The command should accept optional `--artifacts-root` and `--summary-markdown-path` arguments with defaults under `artifacts/`. It should print the summary path and one line per matrix result.

Add a thin script wrapper, `scripts/run_signed_acceptance_evidence.py`, so users who already run repository scripts can use the same flow without remembering the CLI subcommand.

Add tests in a new `tests/unit/test_qa_signed_acceptance_evidence.py` and extend `tests/unit/test_cli_parser.py` plus `tests/unit/test_main_cli.py`. The unit tests should monkeypatch asset generation and matrix execution so they do not run Qt. They should prove success writes a concise summary and failure raises.

Update README to show the one-command evidence command before the manual per-manifest commands. Update `docs/ARCHITECTURE.md` to include the new CLI command and the evidence-runner responsibility under QA/evidence.

The runner is safe to rerun. It overwrites the known generated acceptance inputs and writes matrix run outputs under ignored `artifacts/` directories. If a run fails halfway, rerun the command after fixing the underlying issue; the previous ignored output directory can remain as local diagnostic evidence.
